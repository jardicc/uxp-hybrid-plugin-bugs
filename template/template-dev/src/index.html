Bug #05 SDK CORE BUG (src/utilities/) High Severity • Extreme Native RAM Leak src/utilities/UxpValue.cpp (Value::Value)

Permanent Native C++ Heap Memory Leak When Value Constructor Throws

[SDK Core Bug — affects all plugins using UxpValue] In Value::Value(addon_env, addon_value), data.map = new MapType; is allocated with raw new before calling GetMap(). In C++, if a constructor throws an exception, the object's destructor ~Value() is never executed. By passing an object with 32 keys referencing a single 16 MB JS string (costing only 16 MB in V8) followed by z_fail: null, C++ copies 512 MB of std::string buffers onto the native heap per call and then throws on null — permanently leaking 512 MB / 2 GB / 4 GB of native RAM in Photoshop.exe!

🔴 What Happens When Bug Is Present (Actual): Each call copies 32 × 16 MB = 512 MB into native C++ std::string heap allocations inside *(data.map), then hits z_fail: null, throws "unsupported type", and skips ~Value(). All 512 MB per call is leaked forever in Photoshop.exe!
🟢 Expected Behavior (If Fixed): data.map is managed by std::unique_ptr<MapType> (or deleted in a constructor catch block before rethrowing), so all 512 MB of partial allocations are immediately freed on exception (0 MB leaked).

🟢 Expected Behavior (If Fixed): SDK throws std::runtime_error(...) so catch (const std::exception&) preserves the exact failure reason, UXP_ADDON_INIT / TERMINATE include catch (...), and GetMap() checks recursion depth / visited objects instead of crashing Photoshop.
